# SO-UI-001：SmartOffice 企业后台设计

状态：用户已确认，按第一阶段验证通过后再进入第二阶段执行。需求来源为用户开发指令；接口依据见 [真实接口审计](../../so-ui-001-api-audit.md)。

## 目标与方案

将现有会议室单页扩展为可日常使用的企业后台，普通用户可完成预约、查看个人预约/通知/身份，管理员在同一布局下管理房间、查看全量预约和 Outbox。

采用现有 Vue 3 + TypeScript + Element Plus + Vue Router，新增共享布局与路由页面，复用请求封装、BookModal、requestId 提交协调器和取消协调器。框架和业务一致性实现均不替换。用户已指定技术栈及真实 API 边界，另起一套后台框架或新增后端交易接口都将扩大范围，因此不采用。

## 布局与交互方向（本设计的建议）

- 桌面采用 232px 左侧导航、64px 顶栏与内容区；侧栏可收起，窄屏变抽屉。主内容不因表格过宽导致整页溢出。
- 白色表面、浅灰页面背景、蓝色主色，深色正文；正文与表格 14px，页面标题 24px，统一 8px 圆角、24px 页面间距。
- 顶栏包含当前页面标题/面包屑、真实用户名和用户菜单；用户菜单提供个人中心与退出登录，不放无真实功能的按钮。
- 导航分“办公空间”和“管理中心”：工作台、会议室预约、我的预约、通知中心、个人中心；管理中心为会议室管理、全部预约、Outbox 监控。
- 列表以清晰工具栏和表格/会议室卡片呈现。所有请求有加载、失败重试、空结果状态；失效数据不伪装成正常空列表。
- 可点击控件、键盘焦点、表单标签、图标按钮名称均可识别；支持减少动画设置。具体图标、组件拆分和断点细节交由实现者决定。

## 第一阶段：普通用户完整办公流程

| 路由 | 页面 | 数据与操作 |
|---|---|---|
| `/dashboard` | 工作台 | 真实房间列表、我的订单和最近通知；从成功加载的数据派生个人概览与今日日程，提供预约入口 |
| `/rooms` | 会议室预约 | GET rooms/list；按名称、容量、状态筛选当前列表；保留 BookModal 创建预约流程 |
| `/bookings` | 我的预约 | 独立页面 GET orders/my；已预约/已取消及关键词筛选；真实取消、确认提示和逐行防重复 |
| `/notifications` | 通知中心 | GET notifications/my；展示内容、订单 ID 和时间，提供刷新；无虚假的已读/删除操作 |
| `/profile` | 个人中心 | GET users/me；展示用户 ID、用户名、角色，支持刷新身份及退出；不提供无接口的资料修改 |
| `/forbidden` | 无权限 | 普通用户直接进入管理路由时显示明确拒绝与返回入口 |
| `/login` | 登录/注册 | 保留真实登录/注册和登录错误语义；取消默认填写 demo 密码，登录后恢复合法的站内目标路由 |

### 会话与角色权限

登录成功保存 token 后，通过真实 `/users/me` 建立当前会话；刷新页面同样恢复。布局、菜单和路由守卫共享同一身份状态，并合并并发的身份请求，避免重复加载。

未认证进入保护页跳转登录并携带站内返回路径；身份请求失败时不能默认为普通用户或管理员。401 清除会话，非 401 故障保留重试入口。退出登录清理 token、身份和页面数据，避免另一账号看到前一账号内容。

只有当前有效身份为 ADMIN 且与令牌身份/角色相符时显示管理员菜单并允许管理路由；不一致要求重新登录。令牌解码只作会话一致性检查，不作为可信授权替代。后端 JWT 校验及方法授权继续负责真正的访问控制。普通权限不足的 403 不清除有效登录会话。

## 第二阶段：管理员真实管理能力

| 路由 | 页面 | 数据与操作 |
|---|---|---|
| `/admin/rooms` | 会议室管理 | 真实列表；新增/编辑表单调用 POST/PUT rooms；删除确认后调用 DELETE；失败保留输入或原记录 |
| `/admin/bookings` | 全部预约 | GET orders；在已加载数据上筛选和分页；显示真实用户 ID；调用真实 CSV 导出接口 |
| `/admin/outbox` | Outbox 监控 | GET admin/messages/outbox；状态筛选、刷新、事件详情；明确仅最近 100 条，展示重试次数、租约和错误类型 |

管理员取消其他用户订单只可使用已有取消接口，沿用原取消协调器，后端仍作权限和 CAS 检查。该操作与本人取消一样需要确认，并在成功后更新对应行。

房间表单按实际后端约束校验名称、1～30 人容量、设备数组及 0/1 状态。删除返回 409 时解释有未结束预约，保留该行。维修状态不隐式取消既有订单，也不向用户承诺可预约时段。

CSV 请求显式携带 Bearer 与 Accept: text/csv，只在成功且为 CSV 响应时下载。JSON/Blob 形式的鉴权和业务错误显示为错误，不创建伪 CSV。对象 URL 在下载后释放。后端字段转义与公式防护保持原样。

Outbox 仅提供观察能力，不增加重投、暂停等假操作；SENT 只表示投递状态，不解释为通知已消费成功或 Broker 整体健康。

## 实现边界与文件组织

- `frontend/src/layouts`：共享后台骨架；`views`：每个功能独立页面。
- `api` 与 `types` 补齐当前身份、通知、房间 CRUD、管理订单/导出和 Outbox 契约；不新增第三方状态库或 UI 依赖。
- `composables`/纯工具按必要性复用身份恢复、列表加载及展示转换；不为简单页面抽象大型框架。
- 保持 `/api` 同源代理、既有登录反馈、requestId 和取消互斥语义。筛选/排序/分页只作用于真实已加载结果。
- 不依赖尚未提交的后端新增搜索/测试接口。没有真实数据时显示空态，没有 API 能力时不呈现可执行功能。
- 不改 Java、SQL、Lua、配置、数据库或 Docker 数据。若实际实现发现后端修改不可避免，先单独说明；涉及后端改动必须执行 mvn verify。

## 提交与验收

建议按基础布局/会话权限、普通用户页面、管理员页面、回归测试与文档分成小提交。每次仅暂存本任务明确的 frontend/docs 文件，并核对原有已暂存后端 UserMapper 不进入提交。

1. 基线与完成时执行 npm test、npm run build；新测试覆盖真实 API 路径、身份恢复与拒绝、401/403、独立预约页的取消、CSV 错误及通知/Outbox 数据边界。
2. 在浏览器检查普通用户与管理员导航、直接访问受限路由、刷新与退出、会议室筛选和预约提交、失败重试/重复提交、我的预约取消、通知/个人中心、房间 CRUD 冲突反馈、CSV 下载及 Outbox 只读详情。
3. 验证桌面与窄屏、键盘操作及可见错误态；模拟接口只可作为隔离测试 fixture，产品页面不得用 mock/fallback 数据。
4. 对真实服务开展写入验证前确认隔离测试账号和可清理测试数据范围；不向现有业务数据库任意新增/删除房间或预约。无真实服务可用时准确记录未验证项，不能以浏览器 fixture 测试充当真实集成通过。
5. 核对 Git diff、未提交后端修改及原暂存项仍保留；仅推送 feat/admin-console，创建说明两阶段功能和验收边界的 PR，不合并 main。
